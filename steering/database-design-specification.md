# 数据库设计开发规范（MySQL）

> 适用于提交审核的 MySQL DDL/DML 文件及应用程序中的 SQL 设计。规则按约束力分为【强制】（必须遵守）与【推荐】（尽可能遵守）。

---

## 一、文件与提交

- 【强制】DDL 文件使用 `.sql` 扩展名；DDL 须符合 MySQL 语法。
- 【强制】DDL 内容只保留关键语句与必要注释，注释统一使用 `-- `。
- 【强制】提交审核的 DDL 中去除：`CHARACTER SET`、`COLLATE`、`auto_increment=N`、`engine=`、`row_format=` 子句。

## 二、整体

- 【强制】存储引擎 InnoDB；字符集 utf8mb4；排序规则 utf8mb4_unicode_ci。
- 【强制】不得使用分区表。

## 三、表

- 【强制】必须有表注释，长度 ≤ 64，不得含特殊字符。
- 【强制】表名：小写字母+下划线+数字，字母开头，无连续下划线，非保留字，长度 ≤ 30。
- 【强制】表名使用英文单词/缩写，禁止拼音或拼音缩写；表名围绕核心主体设计。
- 【推荐】表名不使用名词复数形式；不创建备份表/临时表（确需时须经评审）。

### 新表必含字段（顺序不限）

| 字段 | 类型 | 非空 | 默认值 | 注释 |
| --- | --- | --- | --- | --- |
| `id` | 整型 | Y | — | 主键 |
| `creator_id` | varchar(36) | Y | `''` | 创建人id |
| `create_time` | datetime | Y | CURRENT_TIMESTAMP | 创建时间 |
| `last_updater_id` | varchar(36) | Y | `''` | 最后更新人id |
| `last_update_time` | datetime | Y | CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP | 最后更新时间 |

说明：主键可用自增或雪花 ID。日期时间建议由前端传入而非数据库生成。

> **日志/流水表豁免**：仅追加不更新的日志/流水类表（表名含 `_log` / `_flow` / `_journal`）可豁免 `creator_id` / `last_updater_id` / `last_update_time`，但必须保留 `id` 与 `create_time`。

## 四、字段

### 命名

- 【强制】字段名：小写字母+下划线+数字，字母开头，无连续下划线，非保留字，长度 ≤ 30。
- 【强制】使用英文单词/缩写，禁止拼音或拼音缩写；必须有明确正常用途。
- 【强制】字段命名细化到属性级别，不得用主体名充当属性名；以「内容含义」而非「业务功能」视角命名。
- 【强制】避免「关联」「业务」等泛化词；"方/人"区分：专指人用 `er`（中文名「xx人」），含机构用 `pty`（中文名「xx方」）。
- 【推荐】字段名不使用名词复数形式。
- 【推荐】字段名避免使用无主体区分的泛化单一名词（如 `name`、`code`、`status`、`type`、`remark`、`content`），应加所属主体前缀以明确归属（如 `merchant_name`、`order_status`、`secret_remark`）。

### 类型与属性

- 【强制】禁止使用 LOB、TEXT、JSON、enum、set、timestamp、float、double 类型（浮点改 decimal 或 bigint；枚举/时间改 tinyint/datetime）。
- 【强制】禁止存储图片、二进制文件等静态资源，数据库仅存 URL。
- 【强制】新加字段一律追加在表末尾；修改字段用 `MODIFY`/`RENAME`，禁止 `CHANGE COLUMN`。
- 【强制】单表字段数 ≤ 40，超出需重构或经技术委员会评审。
- 【推荐】字段尽量 NOT NULL 并指定默认值。常用类型默认值：
  - 整型 → `0`；decimal → `0.0`；char/varchar → `''`。
- 【推荐】字符串长度够用即可；varchar ≤ 500，char ≤ 20，定长用 char 否则用 varchar。
- 【推荐】数据行长度 ≤ 8020 字节；数字与字符皆可时优先数字类型。
- 【推荐】非特殊情况下不删除字段、不改字段名、不改字段类型（兼容性）。

### 逻辑删除字段

统一使用：

```sql
del_flag tinyint NOT NULL DEFAULT 0 COMMENT '删除标志[0-否,1-是]'
```

## 五、注释

- 【强制】所有表、字段必须有注释；字段注释长度 ≤ 128，不含全角字符；中文标点改英文标点。
- 【强制】字段注释格式：`中文名(补充信息)[枚举信息]`
  - 补充信息：仅写必要补充，无则不写圆括号。
  - 枚举信息：`[key-值,key-值,...]` 或 `[值,值,...]` 或 `[dict:字典值]`；无则不写方括号。
- 注释中英文大小写不做要求（如「id」「ID」均可）。

## 六、索引

- 【强制】唯一索引命名 `uk_字段组合`，普通索引命名 `ix_字段组合`，长度 ≤ 64。
- 【强制】索引字段须与查询条件一致，须执行计划（EXPLAIN）验证有效；查询字段变更后须重新验证。
- 【强制】已建唯一索引的字段不再建相关联合索引；`id` 已有主键索引，不再建普通索引或参与联合索引。
- 【推荐】低区分度字段（状态/类型/是否）不建单字段索引。
- 【推荐】单表索引 ≤ 5 个，联合索引字段 ≤ 5 个。
- ASC、USING BTREE 是否显式书写不做要求。

## 七、视图 / 函数 / 约束 / 触发器 / 过程

- 【强制】不得使用外键约束、触发器、存储过程。
- 【推荐】不使用视图、自定义函数（确需时须经技术管理委员会评审）。

## 八、SQL 语句

### 整体

- 【强制】SQL 须压测：以生产数据量 2–3 倍验证，执行 < 1s；数据 < 10 万时须测 10 万条，执行 < 500ms。

### DQL

- 【强制】禁止 `SELECT *`，须明确指定字段。
- 【强制】统计行数用 `count(*)` 或 `count(1)`，禁止 `count(字段)`。
- 【强制】多表关联时，SELECT 字段须带表名/别名前缀。
- 【强制】必须带 WHERE；WHERE 不得为 `1=1` 等无效条件。
- 【推荐】减少 JOIN 数量；能用 LEFT JOIN 不用 RIGHT JOIN；内连接写 `INNER JOIN` 不简写。
- 【推荐】别名用 `AS` 且含义清晰，避免 t1/a/b 等。
- 【推荐】WHERE 中不对字段做函数转换或计算；不用左模糊 `LIKE '%abc'`；只检索必要字段与行数。
- 【参考】空字符串 `''` 与 `NULL` 不同。

### DML

- 【强制】INSERT 必须列出字段列表。
- 【推荐】UPDATE/DELETE 注意 WHERE 条件，避免误伤。

### DDL

- 【强制】应用程序中禁止任何 DDL 操作。

## 附：提交前自检清单

**文件**：`.sql` 扩展名 / 已去除 engine/charset/collate/auto_increment/row_format / 注释用 `-- `。

**表**：表注释 ≤ 64 / 表名合规 ≤ 30 / 含 5 个必含字段。

**字段**：字段注释 ≤ 128 无全角 / 类型禁用项已规避 / 字段数 ≤ 40 / 命名按属性级别 / `del_flag` 统一。

**索引**：uk_/ix_ 命名 ≤ 64 / 已避开低区分度单字段索引 / id 不重复建索引。

**SQL**：无 `SELECT *` / 有 WHERE / 多表带别名 / INSERT 列字段。
