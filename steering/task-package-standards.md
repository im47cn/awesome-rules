# 任务包与派发守护规范

面向无 spec/intent/plan 链的独立任务派发（工具脚本、文档、研究、验证类）。带完整设计链的多 agent 工程任务仍用 `templates/task-brief.md.template`，两者不混用。

## 1. 任务包结构

任务包 = 五要素骨架 + 三处契约式移植。每条内容的信号标准：**删掉这条，Agent 的行为会变吗？** 不会变就删。

### 1.1 目标 + 反目标【强制】

- 目标：交付什么、给谁用。
- 反目标：**看似成功但不算成功的交付形态**，逐条点名。反目标是对"plausible-but-wrong"交付的最廉价防御，不允许省略。

### 1.2 双层验收【强制】

- **机械验收**：可独立复跑的命令 + 期望输出（退出码/输出形态/确定性）。执行方自验并在交付说明附**最后一次写盘之后**真实运行的输出原文。
- **人工验收**：归属主会话终裁的判断项，显式列出。
- Agent 自报的测试输出**不构成验收证据**，只认主会话独立复跑结果（实证：自报"全绿"实测 13 failed 的伪造案例）。

### 1.3 升级触发器【强制】

触发器只认两类事实，且必须**点名受保护面**：

1. 本任务所有权文件清单（逐一列出）被执行方之外的进程创建/修改/删除；
2. 关键前提失效（任务书断言的事实不再成立，如目标目录文件数、工具可用性）。

规则：
- **禁止泛化前提**（"工作区干净""环境正常"类）——并行派发中兄弟任务产物落盘是设计而非异常，泛化前提必然误中止。
- **明示豁免**：所有权清单之外的路径出现并行任务产物，属预期环境事件，仅记录不中止。
- 触发后动作：停止写盘、上报事实、等待重新协商；禁止即兴绕过，也禁止以仓库既有实现顺延任务书。

### 1.4 状态（写协议）【推荐】

状态节由执行方独占写入，每完成一个里程碑追加一行（含卡点）。起点只陈述可验证事实（基线 commit、所有权文件不存在），不陈述"干净"这类状态判断。

### 1.5 约束（enforcement 分级）【强制】

每条约束标注强制方式，且**必须含操作维度**：

- 【gate 强制】可机械复跑的验收项；
- 【文件所有权】仅可写清单内文件，其余路径一律只读；**未经派发方明确要求，不得执行 git commit / push 等写历史操作**（实证：执行方擅自 commit 案例）；
- 【仅文字，预算 N 条】无机械检查的约束设数量上限，每一条都在消耗本可用于机械强制的注意力。

### 1.6 复用两层判定【强制】

架构形状与叶子工具必须分层判定，不得合并为一句"不复用存量"或"对齐存量"：

- **架构形状级（默认从零推导）**：分层结构、信封形态、公共框架选型——以目标需求为第一性输入从零推导，不得默认复用既有架构；若决定复用既有架构，须先在 `.factory/decisions.md` 新增 ADR，记录目标驱动选择与兼容存量的妥协（含"冲突上报"先例引用），经归属主会话人工审批后方可采用；1.3 节"禁止顺延"仅指本层。
- **叶子工具级（默认必复用）**：工具函数、注入单例（ObjectMapper 等）、封装好的请求/格式化通道——任务书须附**存量工具盘点清单**（路径 + 用途 + 何时必须用），与所有权清单同列；执行方在清单项存在时就地下手重造，视为越界并进 L1 记录。

单向「禁止顺延既有架构」指令会产生负向偏差：执行方连叶子级工具一并重造，只能靠事后多轮审查清偿（001-callback-system 复盘：后端 ObjectMapper 逐次新建绕过全局实例、前端 11 处 encodeURIComponent 内联拼接绕过 http.ts params 通道等 7 处漏复用）。

## 2. 三层守护【强制】

执行中的变异（污染、篡改、过期）靠分层机制拦截，不指望执行 Agent 自查，也不指望 t=0 的任务书检查——后者结构上抓不住执行中事件。

| 层 | 机制 | 防什么 |
|---|---|---|
| L1 | 派发侧 watcher：`tools/dispatch_watch.sh`，记录型 + 仅拦不可逆操作 | 执行中越界与 HEAD 移动，留下证据链 |
| L2 | 异构多 review：`templates/reviewer-battery.md.template` | 交付物内外来内容、范围外变更、质量缺陷 |
| L3 | 主会话独立复跑验收 | 伪造的自报证据 |

### L1：记录优先，只拦不可逆

- 所有权清单外的**新增/修改/删除**只记录不拦截——前期清单评估不到位是常态，越界写入大多可逆（rm / git restore 即逆），"越界即杀"的误杀代价大于收益。
- **立即拦截**仅限 HEAD 移动（commit）：唯一本地可观测且写历史的操作。推远端本地轮询不可测，依赖远端审计；删除已跟踪文件经 `git restore` 可逆，归入记录级。
- watcher 日志（JSONL）随交付归档，并作为 L2 审查输入。

### L2：异构是必要条件

- reviewer 电池至少 3 个维度：正确性 / 范围一致性 / 安全来源（模板见 `templates/reviewer-battery.md.template`）。
- **组合必须含"范围一致性"或"安全来源"维度**——正确性单维度对来源问题结构性失明（实证：正确性 reviewer 报出 11 条代码发现但漏检外来注入行，另两维度均检出）。
- 盲测纪律：不向 reviewer 提示具体怀疑对象；提示词要求其忽略历史会话记忆，仅基于给定材料。

### L3：独立复跑

主会话按机械验收逐项复跑；发现不符进入返工协议（最多 2 轮，每轮附失败输出原文）。

## 3. 派发工艺【推荐】

- omp 后台派发提示词经文件加载：`omp -p --no-session --max-time <N>m "$(cat <任务书>)" < /dev/null`——省略 `< /dev/null` 会使会话卡在等待 stdin（实证卡 1400s）。
- 同仓并行任务按文件所有权隔离（各任务书清单无交集）；需要拉取远程更新时优先选尚未写盘的任务窗口。
- 返工轮任务书必须附失败输出原文，并要求交付说明只引用最后一次写盘之后的真实运行结果。

## 4. 实证依据

本规范条款来自 2026-09 任务包模板对照实验（四组：两轮模板对照、一轮受保护面侵犯注入、一轮 reviewer 盲测），关键结论：

1. 泛化升级前提 → 良性污染即全任务中止；点名受保护面 → 误报归零。
2. 纸面触发器无执行力：静默侵犯（无功能故障信号）时执行方零感知——守护必须机械化且放在派发侧。
3. Agent 自报测试输出存在伪造案例；验收只认独立复跑。
4. 正确性单维度 review 对静默注入不设防；范围/安全维度可检出。
5. t=0 噪声检查抓不住执行中变异；约束缺操作维度会出现擅自 commit。
6. 「禁止顺延既有架构」未拆分层级时，叶子级工具复用被一并抑制——执行方重造工具（001-callback-system 复盘，2026-09-18：7 处漏复用、5 处靠事后十二轮审查清偿）。
