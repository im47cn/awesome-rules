# 架构鹰眼（Arch Hawkeye）需求规格

> 状态：**Phase 1–4 已落地**（2026-08-17）· 需求记法：EARS
> 关联：[[AH-MANIFEST]]（数据契约）、doc-gen（manifest 生产者）、arch-guard（规则源）
> 本文件早期版本曾未入库而丢失，此为按落地实现重建版（需求条目语义不变，补充状态列）

## 1. 背景与定位

`doc-gen` 收缩为「新人 5 分钟看懂一个项目」的单项目入门文档站，专注**单项目**、**详尽**、**人读**。
架构治理（多项目、全局观测、闭环处置）从 `doc-gen` 剥离，独立为**架构鹰眼（Arch Hawkeye）**。

```
doc-gen（初衷1：单项目入门文档）        架构鹰眼（初衷2：全局治理）
├── 产品/技术/领域/API/DB 架构            ├── 跨项目真实链路（5 通道证据）
├── 客户/角色/业务场景/流程/行为/动作      ├── 联邦众包聚合（CI 自注册）
└── 产出 doc-manifest ─────────────┐     ├── 治理闭环（基线/趋势/归属/债务/告警/门禁）
                                   └────▶└── 可查询的架构图 + 仪表盘 + 本地双模式
```

**一句话定位**：doc-gen 让一个人看懂一个项目；架构鹰眼让一群人看清所有项目的架构健康度，并让违规有归宿、有期限、有闭环。

## 2. EARS 语法说明

| 句型 | 中文模板 | 语义 |
|---|---|---|
| **Ubiquitous** | 系统应当 `{响应}`。 | 恒定需求 |
| **Event-driven** | 当 `{触发事件}`，系统应当 `{响应}`。 | 事件触发 |
| **State-driven** | 在 `{状态}` 期间，系统应当 `{响应}`。 | 状态持续时 |
| **Optional** | 若 `{特性已启用}`，系统应当 `{响应}`。 | 特性包含时 |
| **Unwanted** | 如果 `{触发}`，则系统应当 `{响应}`。 | 异常应对 |

优先级：**MVP**（最小可用）/ **P1**（核心价值）/ **P2**（增强）。
状态：✅ 已落地并有测试 / 🚧 部分 / 📋 未做。
