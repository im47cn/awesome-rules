# DDL 脚本无法检查的规则

以下规则 `ddl_check.py` 无法自动检查，审查时需逐表人工判断。

## 命名语义【强制】

| 规则 | 要点 |
|---|---|
| 属性级别命名 | 字段名细化到属性级别，不得用主体名当属性名（如订单表字段不能叫 `order`） |
| 内容视角命名 | 以存储内容含义命名，而非业务功能/逻辑视角 |
| 泛化词 | 避免「关联」「业务」等无信息量词汇，有更精确的词则替换 |
| 方/人区分 | 专指人用 `er`（中文名「xx人」），含机构用 `pty`（中文名「xx方」） |
| 拼音 | 表名/字段名使用英文单词/缩写，禁止拼音或拼音缩写 |
| 表名主体 | 表名围绕核心主体设计 |
| 字段用途 | 字段必须有明确正常用途，不得创建含义不清的字段 |

## 注释质量【强制】

| 规则 | 要点 |
|---|---|
| 补充信息必要性 | 圆括号内容须为必要补充；冗余或让含义混淆的不写 |
| 字段与注释对应 | 字段名与注释含义对应、词汇对应 |

## 设计合理性【推荐】

| 规则 | 要点 |
|---|---|
| 复数形式 | 表名/字段名不使用名词复数（如不加 s） |
| 字符串长度 | 长度以实际内容为准、够用即可 |
| 数据行长度 | 单行不超过 8020 字节 |
| NOT NULL + 默认值 | 字段尽量设 NOT NULL 并指定默认值 |

## 禁用语句【强制】

脚本只解析 `CREATE TABLE`，以下语句类型不会被检出：

| 规则 | 要点 |
|---|---|
| 触发器 | 不得使用 `CREATE TRIGGER` |
| 存储过程 | 不得使用 `CREATE PROCEDURE` |
| 视图/自定义函数 | 【推荐】不使用，确需时须经技术管理委员会评审 |

## 需运行时验证【强制】

| 规则 | 要点 |
|---|---|
| 索引有效性 | 索引字段须与查询条件一致，需 EXPLAIN 验证 |
